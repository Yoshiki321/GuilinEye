## 2. TUIO 1.1 协议对接约定

- **传输格式**：标准 OSC 1.0 二进制 `#bundle` over UDP（`TuioUdpReceiver` 同时兼容单条 OSC message 与文本调试行），支持 `/tuio/2Dcur` 与 `/tuio/2Dblb` 的 `source` / `set` / `alive`（含 0 光标空 `alive` 离场）。
- **`source` 匹配规则**：TUIO 1.1 规范的 `source` 字符串格式为 `application@address`（如 `RadarTool@192.168.1.10`）。`RadarProvider` 与 `InfraredProvider` 同时支持**精确匹配**与 **`source@` 前缀匹配**（例如配置 `"source": "R1"` 可匹配 `"R1"` 或 `"R1@192.168.1.10"`）。
- **端口分配**：调试软件默认多为 UDP `3333`。若雷达与红外在同一主机运行，建议雷达保持 `3333`、红外改为 `3334`；若共用端口则必须保证 `source` 区分明确。

## 3. Femto Bolt 多机部署说明

硬件对照表注明现场 3 台 Femto Bolt 分置不同主机并通过网络汇集运行，联调时按实际拓扑二选一：

1. **分展区主机独立渲染（推荐，与当前架构直接匹配）**：
   - ① 入口主机跑 `GuilinEye.exe -onlyArea A`：`hardware.json` 中仅启用 `S3`（填真实 `serial`，`S1`/`S2` 设 `"enabled": false`）。
   - ③ 亲子主机跑 `GuilinEye.exe -onlyArea C`：`hardware.json` 中仅启用 `S1`、`S2`（填真实 `serial`，`S3` 设 `"enabled": false`）。
   - 各主机通过环境变量 `VENUE_API_URL` 与 `VENUE_OPS_TOKEN` 指向同一台 `venue-api` 服务。
2. **多机采集汇聚到单台渲染主机**：
   - 若现场确需 3 台分机分别接 1 台 Femto 并把体感事件汇总到同一台 Unity 主机，可在各分机运行轻量化深度采集端，将 `presence/point/gesture` 通过 TUIO UDP 发送至主渲染机（待现场确认拓扑后按需补充转发脚本）。
