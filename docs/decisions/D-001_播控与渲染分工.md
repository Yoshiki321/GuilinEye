# D-001 播控与渲染分工决议

版本：1.0｜日期：2026-11-19｜状态：**已决（待 EHE 供货方书面确认 3 项接口后生效）**
对应问题：G-01｜影响：全部 18 个展项、全部服务器与通道

## 1. 事实基线（来自源表，不是推断）

- 08 硬件分配：EHE V1.0 播控融合软件承担 ①2 / ②4 / ③3 / ④15 通道；EHE V1.0 控制播放器 3 台（②③④各 1）。
- ④ 另列“桌面融合系统 15 通道（新增）”。
- 服务器：① P2000/16G ×1｜② P5000/32G ×1｜③ RTX5070/32G ×1｜④ 定制 ×5（1920 方案 3 台、4K 方案 5 台）。
- 投影：24 台全部利旧；单台画面 5800×3260（墙）/5882×3309（地）；① 为 5333×3000。

## 2. 决议

**采用“双层播控”架构，Unity 与 EHE 各守一层，不互相替代。**

| 层 | 承担者 | 职责 |
|---|---|---|
| 内容与实时渲染层 | Unity（每台内容服务器 1 个 Player 实例） | 时间轴、交互、粒子、实时合成；按“投影通道”输出无边框全屏窗口 |
| 播控与融合层 | EHE V1.0 | 通道管理、几何校正、边缘融合、亮度均匀、通道开关、整馆时基、降级播放 |

- Unity **不做**几何校正与边缘融合，只输出每通道的“净幅画面”。
- EHE **不做**实时内容生成，只负责把 Unity 窗口按融合关系投到投影机。
- ① 的 B1/B2 双机叠加：Unity 只输出 **1 路** 5333×3000，EHE 复制到两机并各自做几何校正（降低 P2000 负载）。
- ② P1—P4 各 1 路；③ P5、P6 各 1 路（8500 拼接由 EHE 做融合），P7 1 路；④ P8—P22 共 15 路。

**通道与服务器分配**

| 区域 | 服务器 | Unity 窗口数 | 通道 |
|---|---|---|---|
| ① | P2000/16G ×1 | 1 | B1—B2（EHE 复制） |
| ② | P5000/32G ×1 | 4 | P1—P4 |
| ③ | RTX5070/32G ×1 | 3 | P5—P7 |
| ④（4K 方案） | 定制 ×5 | 15（每台 3 路） | P8—P22 |
| ④（1920 方案） | 定制 ×3 | 15（每台 5 路） | P8—P22 |

## 3. 时基与指令接口

1. **整馆唯一时基由 EHE 控制播放器提供**。Unity 各实例不自行走总时钟。
2. EHE → Unity：UDP 组播，25 Hz，JSON 单行报文：
   - `{"t":"TIME","show":<秒>,"seg":"D03","state":"play|pause|seek"}`
   - `{"t":"CMD","cmd":"pause|resume|segment|volume","arg":"D02","value":0.8}`
3. Unity → EHE：TCP 长连接心跳 + 状态上报（每 1 s）：
   - `{"t":"HB","id":"srv-04-1","fps":60,"seg":"D03","status":"ok|degraded"}`
4. ④ 段切换：EHE 在 3 s 交叉溶解窗口内发 `segment`，Unity 用同一 `show` 时间做本地交叉溶解；**3 s 包含在 720 s 内，不额外加长**（G-22 决议）。
5. 讲解员控幕：EHE 控制播放器 → venue-api `POST /api/control/{pause|resume|segment}` → Unity 订阅同一 UDP 指令。三处使用同一指令格式（G-17）。

## 4. 降级策略

| 故障 | 降级 |
|---|---|
| Unity 单实例崩溃 | EHE 切到该区域预渲染兜底片（①—③ 各 1 条循环；④ 每通道 1 条 720 s） |
| 时基丢失 >2 s | Unity 转本地时钟，EHE 发 `resync`，画面不做黑场 |
| ④ 服务器不足 | 1920 方案：3 台 ×5 路，渲染 2716×1528 上屏；4K 方案：5 台 ×3 路，原生 4K |
| 交互失效 | 模块进入“纯时间轴”模式，保留画面，关闭计分与反馈 |

## 5. 待 EHE 供货方书面确认（不确认则本决议不生效）

1. 是否支持“外部窗口采集/直通”作为通道输入（而非仅视频文件播放）。
2. 是否支持外部时码/自定义 UDP 报文（第 3 节协议）。
3. 桌面融合 15 通道的输出分辨率、刷新率与 EDID 要求。

确认结果写入 `_gate/changes/`，由 Gate 升版；未确认前，任何性能承诺只能标“模拟通过”。

## 6. 对开发 Agent 的约束

- 不得在 Unity 内实现融合、几何校正、投影机开关。
- 不得假设 EHE 能播放 Unity 场景；交互内容必须由 Unity 渲染。
- 所有模块只依赖 `ShowClock` 与 `ControlApi`，不得自建第二套时基。
