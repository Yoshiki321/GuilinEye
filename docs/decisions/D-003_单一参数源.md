# D-003 单一参数源决议

版本：1.0｜日期：2026-11-19｜状态：**已决**
对应问题：G-03｜影响：18 份提示词、全部模块配置、验收基准

## 1. 决议

`仓库/GuilinEye/config/` 下的 JSON 是**全馆唯一参数源**。提示词、项目卡、代码、美术规格一律引用，不得各自写死。

| 文件 | 内容 | 主键 |
|---|---|---|
| `canvas.json` | 四区画布、24 通道、投影机编号、净幅尺寸、重叠与亮度 | `canvasId` / `channelId` |
| `installations.json` | 18 个模块的画面矩形、时间轴、交互、粒子上限、美术槽 | `moduleId` |
| `schedule.json` | ④ 720 s 总轴与各模块循环 | `showId` |
| `sensors.json` | S1—S3、R1—R2、红外覆盖与触点区（T1—T8、九块、热点） | `sensorId` / `zoneId` |
| `quality.json` | 画质档 T1—T4、分辨率、帧率、粒子上限、亮度 | `tier` |
| `art-slots.json` | 91 个画面元素 → 模块 → 美术槽 | `elementId` |
| `contracts/*.json` | 模块间事件与接口 Schema | `$id` |

## 2. 坐标与单位

- 单位统一 **mm**，不使用像素作为业务参数。
- 每个画面以**融合后净幅左下角为原点**，x 向右、y 向上。
- 模块的 `surface` 用 `{canvasId, x, y, w, h}` 表示；`x` 相对净幅左缘。
- 像素换算只在运行期由 `CanvasMapper` 做：`px = mm / surface.w * targetWidth`。

## 3. 加载与校验

1. 启动顺序：`canvas.json` → `quality.json` → `sensors.json` → `schedule.json` → `installations.json` → `art-slots.json`。
2. `tools/validate_config.py` 在任何提交前必须通过：模块数 18、ID 唯一、矩形不越界、时间轴闭合、粒子上限不超档位、91 个元素全部有归槽。
3. 运行期 `ConfigDatabase` 二次校验；失败即进入安全模式（纯色 + 模块名），不得带病上屏。

## 4. 变更规则

- 改参数 = 改 JSON + 跑校验 + 在 `_gate/changes/` 记一条，Gate 升版。
- 提示词里出现具体数字时，必须标注来源键，例如 `（canvas.json#A-WALL）`；没有来源键的数字视为错误。
- Q01（主画布/通道像素）、Q06（九地投映射）在本参数源中已落为可配置项，现场标定只改 JSON，不改代码。

## 5. 与源表的关系

- 源表是**事实来源**，JSON 是**工程化后的唯一可执行表达**；两者冲突时以源表为准并立即修 JSON。
- 源表未定的（如拓本、题库、IP 稿）在 JSON 中标记 `"status":"pending"`，不得填猜测值。
